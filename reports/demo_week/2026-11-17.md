## Follow-up fix: forget no longer resurrects an outdated version

Found by the user's review: page `demo-page` v1 "23 November", v2 "24 November", then a plain file copy of v2; forgetting the copy deleted v2 and reactivated v1, so search answered 23 November. Reactivation is removed locally (`core.py`) and hosted (`c2.sql`). Older versions remain stored as history only; forgetting through the page itself still removes every version, while forgetting through a copy leaves older versions stored (inactive). Side effect kept on purpose: a path whose latest version is inactive no longer counts as a duplicate on re-import (local and hosted), otherwise unforgotten text could stay hidden. Regression tests: `test_forgetting_current_text_does_not_bring_back_an_outdated_version` and the `multi` fixture in `tests/observation_postgres.sql`.

Review of the fix (two checkers and CodeRabbit): no regressions; CodeRabbit's one question (could the new duplicate rule block re-import after history is left behind) was answered by the code and the `multi` fixture. Known gaps, not fixed:
- Forget works on whole versions, not passages: a passage identical in a forgotten version and in an older history version stays stored (and visible through inspect, labelled superseded), though it never reaches search or hybrid search.
- Forgetting through a copy leaves the older version stored as history until it is forgotten separately.
- `hybrid_search` still shows linked copies twice.
- Version numbers can repeat after such a forget (the next import is "version 2" again).
- The `tests/observation_postgres.sql` cross-folder "must not reactivate" check now passes trivially.
